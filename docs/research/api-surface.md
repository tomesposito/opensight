## Reading the inventory and bundle evidence

- `!` / `?` report AWS's documented required / optional members, not new parser
  validation. A documented union requires one member despite optional member flags.
  Objects without a **Union** label are not assigned exclusivity merely because
  they look like alternatives. Lists, ranges, string limits and cross-field
  constraints still require their source pages; this is not a validation schema.
- `K` means the stated camelCase subset is known from the sanitized
  [real fixture](../../fixtures/real-bundle-sample/README.md), inspected locally.
  It is a naming/structure observation, not an API-to-bundle adapter or proof of
  semantic equivalence. Unlisted members of a partially known shape stay unknown.
- `E` means only an empty bundle array was observed; its **item shape is unknown**.
- `U` means no bundle equivalent was observed. Do not generate camelCase bundle
  types from these API names. Map keys/identifiers and acronyms cannot be converted
  mechanically: `QBusinessInsightsStatus` corresponds to the observed
  `qbusinessInsightsStatus`, not a lower-first-letter spelling.

The existing [bundle format notes](bundle-format.md) remain the archive authority.
`Timestamp`, `Long`, enum values and optionality below are documentation-level
types; SDK deserialization and JSON wire encoding are separate unresolved contracts.

## Type additions and validation boundary

`@opensight/bundle-parser` exports the new type-only `QuickSightApi` namespace from
[`api-types.ts`](../../packages/bundle-parser/src/api-types.ts). It adds conservative
PascalCase projections for response bodies, definition roots, fields, field wells,
calculated fields and parameter declarations/defaults. Added detail properties are
optional where documented; required members and explicit unions are checked only
by TypeScript in these new types. Existing type requirements are unchanged.
Referenced presentation/filter/visual bodies not modeled in that file stay opaque.
Timestamp encoding stays `unknown` pending a pinned wire/SDK contract. These types
are for separately obtained API-shaped values, not parser return-type assertions.

The existing `types.ts` synthetic inventory, `bundle-types.ts` camelCase archive
types, validators, parser behavior and query execution allowlist are unchanged.
No new API parsing or validation is introduced. Compile-time consumer checks cover
the additive exports, documented primitive/array shapes and separation from the
synthetic/archive contracts; existing runtime regression suites remain authoritative
for current parsing. The projections add no runtime checks, and their compile-time
checks do not establish AWS validity, size constraints or cross-field rules.
Union annotations differ across the docs: for example, the integer unset-value
configuration is explicitly a union while the other three unset-value pages do
not say so. The new types enforce only explicit shape-level union declarations;
they do not infer further exclusivity from similar field names.

## Still open

- Pin an exact SDK package revision and service-model revision/checksum, then
  capture sanitized definition-response success/error contracts with wire status,
  headers and SDK objects separately before implementing endpoints (§3.2).
- Capture complex sanitized bundles with nonempty calculations, parameters,
  filters, actions and more visuals. All `U`/`E` item mappings remain unproven;
  this catalog does not add archive schemas or a casing conversion adapter.
- Resolve doc/model drift, timestamp/long encoding and conditional requiredness
  (notably topic-versus-dataset binding) against the pinned model and captures.
- Expand the remaining presentation/layout/action/static-file/formatting graph as
  features need it; this inventory is intentionally centered on definition data shapes.
- Establish expression, filter, parameter, query and rendering conformance.
  Recognizing a shape grants neither preservation certification for an unseen
  bundle nor permission for the query engine to execute it.
